# Telegram Mini Apps — 12 готовых приложений

Третий продукт в архиве. Mini Apps — это веб-приложения, которые открываются
**внутри Telegram** по кнопке в боте: полноценный интерфейс вместо переписки с
кнопками. Telegram активно двигает этот формат, и на него сейчас переходят все
серьёзные боты.

Зачем это вам:

- **Допродажа к каждому боту.** «Бот + мини-апп» продаётся дороже бота в
  полтора-два раза при тех же трудозатратах на внедрение.
- **Продаётся отдельно.** Кафе нужно QR-меню, барберу — запись, магазину —
  витрина. Это самостоятельные продукты.
- **Один сервер на все 12.** Не нужен отдельный хостинг под каждое приложение.

## Что внутри

| Приложение | Что делает | Кому продавать |
|-----------|-----------|----------------|
| `shop` | Витрина с корзиной, остатками и оформлением | магазины аккаунтов, товарка |
| `menu` | QR-меню с заказом за столик | кафе, рестораны, бары |

| `loyalty` | Баллы, уровни, списание на скидки | розница, кофейни |

## Главное: почему это безопасно

Mini App получает от Telegram строку `initData` с данными пользователя. Она
**полностью подделываема** — любой открывает devtools и пишет туда чужой ID.
Половина туториалов в интернете разбирает `initData` в браузере и доверяет
полю `user.id`. Такое приложение позволяет любому посетителю выдать себя за
любого клиента и списать его баллы.

Здесь всё наоборот:

- клиент **никогда** не сообщает, кто он — он присылает подписанную строку;
- сервер пересчитывает HMAC-SHA256 по алгоритму Telegram и сравнивает
  подписи в постоянном времени;
- проверяется срок жизни payload (защита от повтора перехваченной сессии) и
  метка из будущего;
- ни одно приложение не читает `initDataUnsafe` — это проверяется тестом по
  всем 12 приложениям.

Подделанная подпись, чужой токен бота, подменённый ID, дописанное поле,
просроченный payload — всё отклоняется. На это 15 отдельных тестов.

## Быстрый старт

```bash
pip install -r requirements.txt
export BOT_TOKEN=123456:AA...       # тот же бот, к которому крепятся апы
python serve.py                      # http://localhost:8100
```

Подключение к боту:

1. [@BotFather](https://t.me/BotFather) → `/mybots` → ваш бот → Bot Settings →
   Menu Button → указать `https://ваш-домен/app/shop/`
2. Или кнопкой в самом боте:
   ```python
   from aiogram.types import InlineKeyboardButton, WebAppInfo
   InlineKeyboardButton(text="🛍 Открыть витрину",
                        web_app=WebAppInfo(url="https://ваш-домен/app/shop/"))
   ```

Telegram требует **HTTPS** — на локалхосте приложение не откроется. Для
разработки подойдёт `cloudflared tunnel` или `ngrok`.

Docker:

```bash
cp .env.example .env && nano .env
docker compose up -d
```

systemd:

```bash
sudo cp miniapps.service /etc/systemd/system/
sudo systemctl enable --now miniapps
```

## Как устроено

```
miniapps/
├── core/auth.py     проверка подписи initData — самое важное здесь
├── core/server.py   FastAPI: раздаёт апы, проверяет каждый вызов
├── core/store.py    SQLite: состояние пользователей и заявки
├── shared/tg.js     обёртка над Telegram SDK, тема, MainButton, API
├── shared/app.css   оформление под тему Telegram (светлая и тёмная)
└── apps/<slug>/     app.json (данные) + index.html (логика)
```

Каждое приложение — одна HTML-страница без сборки, без npm, без зависимостей.
Открыл, поправил `app.json` под клиента, отдал.

## Что менять под клиента

Почти всё живёт в `apps/<slug>/app.json`:

| Поле | Что это |
|------|---------|
| `title`, `summary` | название и описание |
| `catalog` / `sections` / `services` | товары, меню, услуги |
| `admin` | Telegram ID владельца — только он видит заявки |
| `thanks` | текст после отправки |
| `currency` | валюта |

Вёрстку менять не нужно — она подстраивается под тему Telegram
пользователя автоматически, включая тёмную.

## Заявки

Всё, что отправляют пользователи (заказы, записи, отзывы, обращения),
складывается в SQLite и доступно владельцу:

```
GET /api/<slug>/submissions
```

Доступ только у тех, чьи ID указаны в `admin` манифеста — не у того, кто
попросит.

## Ограничения — честно

- Нужен домен с валидным HTTPS. Без него Telegram не откроет приложение.
- Приложения работают с демо-данными из `app.json`. Витрина не знает про
  реальный склад бота, трекер показывает демо-этапы — подключение к вашей
  базе делается на месте под конкретного клиента.
- Оплата внутри Mini App здесь не реализована: оформленный заказ уходит в
  бота, и счёт выставляет он. Так проще и клиенту, и вам — вся платёжная
  логика уже отлажена в движке ботов.
